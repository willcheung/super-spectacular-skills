# Public release gates

## Scope and positioning
Publish a generic evidence-backed wiki operating skill inspired by Andrej Karpathy's LLM Wiki pattern. Do not imply endorsement, a novel retrieval algorithm, or benchmark superiority. Differentiators: provenance, contradiction retention, freshness discipline, canonical ownership, handoff verification, and fail-closed privacy.

Exclude original corpus, domain-specific rules, identity, account data, paid collectors, operational logs, dashboards, and private history.

## v0.1 boundary
Included: instructions, templates, a complete fictional example wiki, and behavioral acceptance specifications.
Not included: executable initializer, index generator, linter, export adapter, scheduler, or CI. Never market planned tooling as implemented.

## Before publication
- Confirm owner/repository, target branch, license, attribution, and publication method.
- Start with clean public files/history; never push private wiki history.
- Review every allowlisted file for private identifiers/paths, secrets, source content, and infrastructure.
- Check copied material licenses and redistribution rights separately from conceptual attribution.
- Include README, chosen LICENSE, and notices as needed.
- Add fictional evidence/example and executable tests before claiming automated features.
- Scan working tree and all intended commits for secrets/privacy.
- Obtain explicit publication authorization; verify remote SHA, file list, and visibility afterward.

## Recommended next release
Portable initialization, deterministic index generation, link/frontmatter/evidence lint, and synthetic tests. Read taxonomy from one shared registry. Keep adapters optional; avoid an application/database until measured gains justify it.
